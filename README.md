# Node.js Starter

A minimal template for building a [Node.js](https://nodejs.org/en) library in [TypeScript](https://www.typescriptlang.org/) with [ESM](https://nodejs.org/api/esm.html) support and an optional CLI. Type checking, linting, and formatting are enforced on every commit, tests with 100% coverage run on every pull request, and every tag you push gets a draft GitHub release with the packed package attached. Publishing the draft then stages the same package on npm.

## Getting Started

Create a new repository from this template on GitHub using [this link](https://github.com/new?template_name=nodejs-starter&template_owner=threeal), or clone it locally and point it at your own remote.

## Setup

Install [pnpm](https://pnpm.io/), then install dependencies:

```sh
pnpm install
```

Install [Lefthook](https://lefthook.dev/), then register the pre-commit hook:

```sh
lefthook install
```

## Customizing

Replace or extend the template files to fit your project:

- **`src/`** — Replace the placeholder library, CLI, and tests with your own code.
- **`CLAUDE.md`** — Replace with guidance specific to your project.
- **`LICENSE`** — Replace with your preferred license, or keep the [Unlicense](https://unlicense.org/).
- **`package.json`** — Update the package name, description, version, and other metadata.
- **`README.md`** — Replace with a description of your project.

If your project doesn't need a CLI, remove `src/cli.ts`, the `bin` entry in `package.json`, and the `yargs` and `@types/yargs` dependencies.

## Development

Run the tests with coverage through Vitest:

```sh
pnpm vitest run
```

The project enforces 100% code coverage, counting only files the tests import.

Each `git commit` runs the pre-commit hook registered during setup, which checks your changes and fixes what it can in place. If it fails, fix any reported issues, re-stage the changed files, and commit again.

After committing, push to `main` or open a pull request from another branch — CI will run the same checks across all files, plus additional checks of its own.

## Releasing

Update the version in `package.json`, then push a version tag to create a draft release with notes generated by GitHub and the packed tarball attached. Review the draft on GitHub, edit the notes if needed, and publish it when it's ready.

To also publish to the [npm registry](https://www.npmjs.com/), add an [npm access token](https://docs.npmjs.com/creating-and-viewing-access-tokens) with publish rights as the `NPM_TOKEN` repository secret. Publishing the draft then [stages](https://docs.npmjs.com/staged-publishing) the same tarball on npm, where you approve it to make it public.

Once the package exists on npm, you can replace the token with [trusted publishing](https://docs.npmjs.com/trusted-publishers/): add a trusted publisher on npm for your repository and `publish.yaml`, then delete the `NPM_TOKEN` secret after a release has staged through it.

If your project isn't published to npm, remove `.github/workflows/publish.yaml`.
